# wezterm

本ドキュメントは、wezterm element が管理する設定の内容と、適用先の外で必要となる設定を扱う。

Windows 上の端末として用いる WezTerm の設定である。設定の全体を管理し、適用のたびにファイル全体を置き換える。

適用先は `%USERPROFILE%\.config\wezterm\wezterm.lua` である。WezTerm は Windows でもこのパスを設定ファイルの探索対象に含む。あわせて、セッションの状態の保存先である `%USERPROFILE%\.config\wezterm\state\workspace\` を作成する。保存されるファイルは管理対象に含まない。

WSL 上の tmux で用いていた操作と表示を、WezTerm のタブ、ペイン、タブバーへ対応付けている。tmux から移した設定には、対応する tmux の設定を併記する。

## 接続先

既定の接続先は `WSL:Ubuntu-24.04` である。起動時と、タブおよびペインの新規作成時のいずれも、WSL 上のシェルが開く。

接続先を指定して新しいタブを開く手段は 3 つある。Alt+1 から Alt+3 のキー、タブバー右端に並ぶ一覧に添えた同じ数字、および launcher menu である。launcher menu は WezTerm のネイティブ UI であり、タブバーの新規タブボタン (+) の右クリック、または Alt+Shift+w で開く。新規タブボタン (+) の左クリックは、既定の接続先でタブを開く。

指定できる接続先を、以下にまとめる。短縮名はタブバー右端に並ぶペイン一覧と接続先の一覧に表示する名前であり、色はその 2 つの一覧の文字色と、タブの文字色および背景色に用いる。

| 項目 | 短縮名 | 色 | キー | 接続先のドメイン | 起動するプログラム |
| --- | --- | --- | --- | --- | --- |
| WSL: Ubuntu-24.04 | WSL | 緑 (`#98c379`) | Alt+1 | `WSL:Ubuntu-24.04` | ディストリビューションの既定のシェル |
| PowerShell | PS | 青 (`#61afef`) | Alt+2 | `PowerShell` | `powershell.exe -NoLogo` |
| Command Prompt | CMD | 黄 (`#e5c07b`) | Alt+3 | `local` | `cmd.exe` |

起動するプログラムはドメインが定める。`PowerShell` は WezTerm の exec domain であり、そのドメインで起動する SpawnCommand を `powershell.exe -NoLogo` へ置き換える。`local` ドメインは、プログラムの指定が無い場合に `cmd.exe` を起動する。

ペインの分割は、分割元のペインと同じドメインで行う。起動するプログラムはドメインが定めるため、PowerShell のペインを分割すると PowerShell のペインが増える。

> [!NOTE]
> PowerShell を `local` ドメインと分けるのは、ペインの種別の判別とセッションの復元が、いずれもペインの属するドメイン名から起動するプログラムを定めるためである。同じドメインへ置くと、Command Prompt のペインと区別できない。

> [!NOTE]
> タブバー右端のペイン一覧と接続先の一覧は、いずれもクリックできない。WezTerm がタブバーへ置けるボタンは新規タブボタン (+) の 1 つに限られ、任意の位置へボタンを足す手段が無いためである。

## カレントディレクトリ

新規のペインと新規のタブは、直前にいたペインのカレントディレクトリを引き継ぐ。接続先を指定して開くタブが引き継ぐのは、指定した接続先のドメインが直前にいたペインのドメインと同じ場合に限る。

引き継ぐ値は、タブ名とペイン一覧に表示するカレントディレクトリ名、およびブランチ名を探す起点と同じものである。Windows 側のペインではプロセスから、WSL のペインではシェルが OSC 7 で通知した値から得る。

引き継がない場合に開く位置は、接続先のドメインが定める。WSL のドメインは WSL 上のホームディレクトリ、Windows 側のドメインは Windows のホームディレクトリである。引き継ぐ先を持たない起動時のペインは、既定の接続先が WSL であるため WSL 上のホームディレクトリで開く。

> [!NOTE]
> WSL のドメインの位置は、WezTerm が `wsl.exe` へ渡す `--cd` に `~` を指定して定めている。指定が無い場合、WSL のペインも Windows のホームディレクトリで開き、WSL からは `/mnt/c/Users/<ユーザー名>` として見える。

> [!IMPORTANT]
> WSL のペインで OSC 7 の通知が無い場合、WezTerm が得るのは Windows 側から見た `wsl.exe` のカレントディレクトリである。WSL 上のカレントディレクトリとは一致しないため、タブ名とペイン一覧の表示、ブランチ名、および新規ペインの引き継ぎのいずれもが実際の位置とずれる。通知の設定は [WSL 上のシェルによる OSC 7 の通知](#wsl-上のシェルによる-osc-7-の通知) を参照。

## キー割り当て

tmux の window はタブ、pane はペインへ対応する。WezTerm の既定のキー割り当ては残し、以下の分のみを上書きする。

| キー | 動作 | 対応する tmux の設定 |
| --- | --- | --- |
| Ctrl+a | leader | `set -g prefix C-a` |
| Ctrl+a Ctrl+a | Ctrl+a を接続先へ送る | `bind-key C-a send-prefix` |
| Ctrl+a r | 設定の再読み込み | `bind-key r source-file` |
| Ctrl+a s | セッションの保存 | tmux-resurrect の prefix + Ctrl-s |
| Alt+Shift+w | launcher menu を開く | - |
| Alt+1, Alt+2, Alt+3 | 接続先を指定したタブの新規作成 | - |
| Alt+w | タブの新規作成 | `new-window` |
| Alt+d | タブを閉じる。確認を求める | `confirm-before 'kill-window'` |
| Shift+Left, Shift+Right | 前後のタブへ移動 | `previous-window`, `next-window` |
| Alt+\ | ペインを左右へ分割 | `split-window -h` |
| Alt+- | ペインを上下へ分割 | `split-window -v` |
| Alt+Delete | ペインを閉じる。確認は求めない | `kill-pane` |
| Alt+z | ペインのズームの切り替え | `resize-pane -Z` |
| Alt+方向キー | 隣のペインへ移動。端では折り返さない | `select-pane` |
| Alt+[, Alt+] | ペインの幅を 5 桁ずつ増減 | `resize-pane -L 5`, `resize-pane -R 5` |
| Alt+PageUp, Alt+PageDown | ペインの高さを 5 行ずつ増減 | `resize-pane -U 5`, `resize-pane -D 5` |
| Alt+a | コピーモードへ入る | `copy-mode` |
| コピーモード中の y, Enter | コピーして抜ける | `copy-pipe-and-cancel` |
| Alt+h | キー割り当ての一覧を表示する | `list-keys` |

WezTerm の `copy_mode` キーテーブルは vi のキー操作を既定に持ち、tmux の `mode-keys vi` に対応する。既定でコピーへ割り当てられているのは `y` のみであるため、`Enter` を同じ動作へ差し替えている。コピー先は Windows のクリップボードである。

Alt+h が開く一覧は、上の表と同じ内容を区分ごとに並べたものである。表示は WezTerm の InputSelector によるオーバーレイであり、Esc で閉じる。項目の選択は何も行わない。

## タブバー

tmux の status line に対応する表示は、すべて WezTerm のタブバーで行う。タブバーの背景は端末画面の背景より明るく、タブとペイン一覧が占める領域はタブバーの地よりさらに明るい。端末画面とタブバー、およびタブバーの中の領域の境目を、いずれも明度の差が示す。タブバーは上端に置き、タブが 1 つのときも隠さない。表示する内容が多いため、等幅で並ぶ retro tab bar を用いる。retro tab bar は端末の 1 行として描かれるため、縦幅は端末のフォントの大きさが定める。

タブバーは 1 行を 4 つの領域で分け合う。左端はタブであり、右端にはブランチ名、ペイン一覧、接続先の一覧をこの順で並べる。領域ごとの内容を、以下にまとめる。

| 領域 | 内容 | 対応する tmux の設定 |
| --- | --- | --- |
| 左端 | タブの一覧と新規タブボタン (+) | window の一覧 |
| 右端の左端 | アクティブなペインのブランチ名 | `pane-border-format` |
| 右端の中央 | アクティブなタブのペイン一覧 | `status-format[1]` |
| 右端の右端 | 接続先の一覧 | `status-format[0]` の右端 |

ブランチ名は、アクティブなペインのカレントディレクトリが属する Git リポジトリのものである。カレントディレクトリから根まで遡り、最初に見つかった `.git` の `HEAD` を読む。`HEAD` がコミットを直接指す場合は、ブランチ名の代わりにコミットハッシュの先頭 7 桁を表示する。リポジトリの外では何も表示しない。文字色はどの接続先の色とも異なるため、ペイン一覧のカレントディレクトリ名と区別できる。

ブランチ名の表示は、ペインのカレントディレクトリの変化から最大 3 秒遅れる。WezTerm はタブバーを 1 秒ごとに更新するため、更新のたびに `HEAD` を読むことを避け、直近に調べた結果を 3 秒間用いるためである。

ペイン一覧は、アクティブなタブに属するペインを、接続先の短縮名とカレントディレクトリ名の組で並べる。短縮名の文字色は接続先の種別を表し、色と接続先の対応は [接続先](#接続先) を参照。アクティブなペインは、背景色を一覧の中でさらに明るくし、太字と明るい文字色で強調する。ズームしているペインには `Z` を付ける。表示のみであり、クリックによるペインの選択はできない。ペインの選択は Alt+方向キーで行う。

ペイン一覧が占める領域は、タブバーの地より明るい背景色で示す。接続先の一覧との間には空白 3 文字分を置く。

WezTerm はペインごとのヘッダを持たないため、ペインの情報はこの一覧とブランチ名が担う。tmux の `pane-border-status` と `pane-border-format` による、ペインの境界への情報の表示に対応する位置付けである。

タブは、カレントディレクトリ名のみを置く。接続先の種別は短縮名では表さず、カレントディレクトリ名の色が表す。色と接続先の対応は [接続先](#接続先) を参照。カレントディレクトリ名は tmux の `automatic-rename-format "#{b:pane_current_path}"` に対応する。

タブとタブの間、およびタブバーの左端とタブの間には、タブバーの地が空白 1 文字分ずつ覗く。アクティブなタブは接続先の色を背景色とし、文字を暗い側の色とする。アクティブでないタブは、タブの領域の背景色に接続先の色の文字を置く。アクティブでないタブの明度を落とさないため、どのタブもカレントディレクトリ名を同じ読みやすさで表示する。

接続先の一覧は、[接続先](#接続先) の短縮名を Alt+数字 の数字とともに並べる。文字色は接続先の色であるため、タブの色から接続先を読み取る対応表を兼ねる。leader を押している間は、この一覧の左へ、leader に続くキーの一覧を添える。

キー割り当ての一覧はタブバーへ常時は置かない。1 行をペイン一覧とタブが分け合う以上、桁数を確保できないためである。一覧は Alt+h が表示する。

領域の合計がタブバーの桁数を超えると、右端から順に表示が欠ける。これを避けるため、ペイン一覧はカレントディレクトリ名のみを置き、ブランチ名は 24 桁で切る。

> [!NOTE]
> タブバーは 1 行に限られる。WezTerm が持つタブバーは 1 つであり、`tab_bar_at_bottom` はその位置を上端と下端の間で移すのみである。行を増やす設定と、タブバーとは別の status 行を置く設定は無い。

## ペインとウィンドウの見えかた

非アクティブなペインは、文字と背景を暗くして表示する。tmux の `window-style` と `window-active-style` による色分けに対応する。加えて、分割したペインの間には区切り線を引く。

ウィンドウの背景は不透明とする。1.0 未満の不透明度と、それを前提とする Acrylic は、背後のウィンドウとデスクトップの色を映して画面全体の明度を上げ、配色が定める色より明るく見せるためである。

起動時のウィンドウの大きさは 200 桁 60 行である。WezTerm の既定である 80 桁 24 行の 2.5 倍に当たる。

フォントは Consolas と BIZ UDGothic の組み合わせ、配色は OneHalfDark である。

## セッションの保存と復元

ウィンドウ、タブ、ペインの構成を定期的に保存し、次の起動で復元する。tmux-resurrect と tmux-continuum によるセッションの保存と復元に対応する。WezTerm 自体は構成の保存と復元を持たないため、[resurrect.wezterm](https://github.com/MLFlexer/resurrect.wezterm) プラグインが行う。プラグインの取得に必要な条件は、[resurrect.wezterm プラグインの取得](#resurrectwezterm-プラグインの取得) を参照。

保存の内容を、以下にまとめる。

| 項目 | 値 |
| --- | --- |
| 対象 | アクティブな workspace に属するウィンドウ、タブ、ペイン |
| 保存する値 | ペインの配置、接続先のドメイン、カレントディレクトリ、ズームの状態、ウィンドウの大きさ |
| 保存するスクロールバック | local ドメインのペインの末尾 1000 行 |
| 間隔 | 60 秒 |
| 保存先 | `%USERPROFILE%\.config\wezterm\state\workspace\` |

復元は起動時に行う。復元したペインは、保存した接続先のドメインとカレントディレクトリで起動する。起動するプログラムはドメインが定めるため、接続先は保存した時点と同じものとなる。

復元するのは構成であり、ペインで動いていたプログラムのプロセスは復元しない。プロセスは WezTerm の終了とともに終わるためである。local ドメインのペインが alt screen を用いるプログラムを前面に持っていた場合に限り、そのコマンドを復元したペインへ入力する。

スクロールバックの復元は local ドメインのペインに限る。WSL のペインの内容は保存しない。プラグインが復元に用いる出力の注入が、local ドメインでのみ行えるためである。

Ctrl+a s は、間隔を待たずにその時点の構成を保存する。保存する内容と保存先は定期的な保存と同じであり、次の起動はこの保存を復元する。tmux-resurrect の prefix + Ctrl-s に対応する。

> [!IMPORTANT]
> 定期的な保存は 60 秒ごとに行い、WezTerm の終了時には行わない。WezTerm が終了時のイベントを持たないためである。最後の保存から終了までの変更は復元されないため、終了の前に構成を残す場合は Ctrl+a s で保存する。

> [!NOTE]
> 保存の繰り返しは、設定を評価するたびに開始し直す。繰り返しの予定は設定を評価し直した時点で失われるため、開始済みを記録して 2 回目以降の評価で開始を省くと、保存が一度も行われない。

> [!NOTE]
> 復元は WezTerm の起動ごとに行う。WezTerm を 2 つ起動した場合、いずれもが保存した構成を復元する。

## 対応する設定が無い操作

tmux で用いていた操作のうち、WezTerm へ移していないものと、その理由を以下にまとめる。

| tmux の設定 | 内容 | 理由 |
| --- | --- | --- |
| `select-layout` | ペイン配置のプリセット | WezTerm に対応する機能が無い |
| `detach-client` (Alt+F12), `kill-server` (Alt+F11) | クライアントのデタッチとサーバの終了 | WSL のドメインは multiplexer サーバを介さないため、対象が無い |
| `pane-border-format` | ペインヘッダへの Git リポジトリ名の表示 | WezTerm はペインごとのヘッダを持たない。リポジトリの位置はタブバー右端のペイン一覧のカレントディレクトリ名が表す。ブランチ名はタブバー右端の左端が表す |

## 適用先の外で必要となる設定

本節は、wezterm element が管理する設定の動作に、適用先の外で必要となる設定と条件を扱う。

### resurrect.wezterm プラグインの取得

セッションの保存と復元は [resurrect.wezterm](https://github.com/MLFlexer/resurrect.wezterm) プラグインが行う。設定の読み込みの時点でプラグインが未取得であれば、WezTerm が GitHub からプラグインを複製する。複製の位置は `%APPDATA%\wezterm\plugins` であり、chezmoi の適用先には含まれない。

初回の起動には GitHub への接続を要する。接続できない場合、設定の読み込みが失敗し、WezTerm は既定の設定で起動する。複製の後は接続を要さない。

> [!NOTE]
> resurrect.wezterm が依存する [dev.wezterm](https://github.com/chrisgve/dev.wezterm) も、同じ位置へ複製する。

### WSL 上のシェルによる OSC 7 の通知

WSL のペインのカレントディレクトリは、WSL 上のシェルが OSC 7 で通知した値による。通知が無い場合、WezTerm が得るのは Windows 側から見た `wsl.exe` のカレントディレクトリであり、WSL 上の位置とは一致しない。WSL 側で `~` にいるペインのタブ名が `<ユーザー名>` (`C:\Users\<ユーザー名>`) となるのは、この状態である。

WezTerm はカレントディレクトリを表示と新規ペインの双方で用いるため、通知が無いと以下がまとめてずれる。

| 対象 | 通知が無い場合の値 |
| --- | --- |
| タブ名 | `wsl.exe` のカレントディレクトリ名 |
| ペイン一覧のカレントディレクトリ名 | `wsl.exe` のカレントディレクトリ名 |
| ブランチ名 | `wsl.exe` のカレントディレクトリが属する Git リポジトリのブランチ名 |
| 新規のペインと新規のタブが引き継ぐカレントディレクトリ | `wsl.exe` のカレントディレクトリ |

通知は接続先のシェルが行う。WSL2 の profile が選ぶ wezterm-shell element が、通知を行うシェル統合スクリプトの配置と読み込みを管理する。スクリプトが送出する制御列は、[WezTerm のシェル統合](../wezterm-shell/README.md) を参照。
